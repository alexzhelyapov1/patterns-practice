### 🛠 Шпаргалка: Strategy (Стратегия)

**Проблема:** Огромные конструкции `if/else` или `switch` для выбора алгоритма, которые заставляют основной класс знать обо всех реализациях сразу.

**Решение:** Вынос каждого алгоритма в отдельный класс-стратегию и делегирование выполнения через общий интерфейс (динамика) или шаблон (статика).

---

#### ✅ Плюсы и ❌ Минусы
*   ➕ **Open/Closed Principle:** Новые алгоритмы добавляются без правки существующего кода.
*   ➕ **Изоляция:** Логика и данные алгоритма не перемешиваются с бизнес-логикой контекста.
*   ➕ **Runtime Switch:** Возможность сменить поведение объекта прямо во время работы (в динамической версии).
*   ➖ **Overengineering:** Если алгоритма всего два и они никогда не изменятся, `if` проще.
*   ➖ **Осведомленность:** Клиент должен понимать различия между стратегиями, чтобы выбрать нужную.

---

#### 💻 Code Snippet (Modern C++)

**Динамическая (Runtime):**
```cpp
struct IStrategy {
    virtual ~IStrategy() = default;
    virtual void execute() const = 0;
};

class Context {
    std::unique_ptr<IStrategy> strategy;
public:
    void set_strategy(std::unique_ptr<IStrategy> s) { strategy = std::move(s); }
    void run() const { if (strategy) strategy->execute(); }
};
```

**Статическая (Compile-time):**
```cpp
template<typename T>
concept Strategy = requires(const T s) { { s.execute() } -> std::same_as<void>; };

template<Strategy S>
class Context {
    S strategy;
public:
    void run() const { strategy.execute(); }
};
```

---

#### 🚫 Когда НЕ использовать
1.  **Тривиальность:** Если логика занимает одну строку, проще использовать `std::function` или лямбду.
2.  **Отсутствие изменений:** Если набор алгоритмов жестко фиксирован и никогда не будет расширяться.
3.  **Сложность данных:** Если алгоритмам нужны глубокие интимные знания о полях контекста (нарушится инкапсуляция).
